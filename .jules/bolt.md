## 2025-03-05 - Avoided N+1 in HyDE RAG implementation
**Learning:** Found an N+1 query pattern in `AdaptiveRAGRouter._execute_hyde_rag` where document embeddings were being queried sequentially inside a loop (`await self.embeddings.aembed_documents([doc.page_content])`). This creates an individual network/API roundtrip for each retrieved document, heavily penalizing performance as document counts grow.
**Action:** Extract all document strings and process them in a single batch using `await self.embeddings.aembed_documents(doc_contents)`, then zip the resulting embeddings back with the original documents. Apply this optimization to both locations (`src/ippoc` and `infra/src`) that implement `AdaptiveRAGRouter`.
