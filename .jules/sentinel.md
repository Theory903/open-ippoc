## 2025-02-06 - Default Insecure Configuration
**Vulnerability:** Hardcoded API key ("ippoc-secret-key") used as default in `src/cortex/cortex/server.py`.
**Learning:** Default configurations for development often make their way into production or expose systems during testing if not explicitly overridden. The system relied on a specific hardcoded string for default auth, which is a Critical vulnerability (CWE-798).
**Prevention:** Never provide a hardcoded default for secrets. If a secret is missing, either generate a secure random one at runtime (fail-safe) or refuse to start (fail-secure).
## 2024-05-09 - Command Injection in Telegram Integration
**Vulnerability:** A critical command injection vulnerability existed in `_integrate_telegram` inside `openclaw_tool_integrator.py` because a dynamically generated user path (`tg_path`) was injected into a Python execution string using f-string interpolation.
**Learning:** Even when the source of a variable seems somewhat constrained (like `Path.home()`), any dynamically constructed paths can potentially be exploited if a malicious actor controls directory creation or path generation. Relying on string interpolation for subprocess execution is an anti-pattern because special characters (like quotes) within the string can break out of the string boundary, causing arbitrary code execution.
**Prevention:** Never use f-strings or string concatenation to pass arguments into dynamic script executions via `subprocess.run()`. Always use `sys.argv` (or similar standard argument passing techniques) to retrieve parameters injected via the subprocess arguments list.
